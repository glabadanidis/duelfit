# DuelFit

Sports prediction duels with physical forfeits. Two friends pick opposite sides on a real
upcoming match. The loser does the forfeit they agreed on before the match started.

No money. No betting. No odds. The stake is always physical.

React Native (Expo) app on Supabase. Pre-launch, not yet submitted to either store.

## Run it locally

Requires Node 20 or later and the Expo Go app on a physical phone. Push notifications and
the F1 flow do not work in a simulator, so use a real device.

```bash
git clone https://github.com/glabadanidis/duelfit.git
cd duelfit
npm install
```

Create a `.env` file in the repo root. It is gitignored and has never been committed.

```
EXPO_PUBLIC_SUPABASE_URL=https://nofawxywnhqrqnwokkge.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=<anon key from Supabase dashboard, Settings > API>
```

The anon key is safe on a client. Row Level Security is what protects the data, not the key.
The **service role key must never appear in this repo or in a `.env` file here.** It lives only
in the Supabase edge function environment.

```bash
npm start        # Metro bundler, then scan the QR code with Expo Go
npm run ios      # opens an iOS simulator
npm run android  # opens an Android emulator
```

Any change to `.env` requires a full restart of Metro. `EXPO_PUBLIC_` variables are inlined at
bundle time, so a hot reload will not pick them up.

## Build and release

Builds run on EAS, not locally. There is no `ios/` or `android/` directory in the repo, both are
generated by prebuild during the EAS build.

```bash
npm install -g eas-cli
eas login
eas build --platform ios --profile production
eas build --platform android --profile production
eas submit --platform ios --latest
```

**EAS never sees your local `.env`.** Builds run on Expo's servers, so the two Supabase variables
have to exist on EAS as well or the build installs and then fails to reach Supabase on every screen.
Set them once per environment:

```bash
eas env:create --name EXPO_PUBLIC_SUPABASE_URL \
  --value "https://nofawxywnhqrqnwokkge.supabase.co" \
  --visibility plaintext --environment preview --environment production

eas env:create --name EXPO_PUBLIC_SUPABASE_ANON_KEY \
  --value "<anon key>" \
  --visibility plaintext --environment preview --environment production

eas env:list
```

If a build logs `No environment variables with visibility "Plain text" and "Sensitive" found`, this
is what is missing.

Profiles in `eas.json`:

| Profile | What it is for |
|---|---|
| `development` | Dev client, internal distribution. Use when a native module changes. |
| `preview` | Internal distribution, real device (`simulator: false`). Share a build with a tester. |
| `production` | Store builds. `autoIncrement: true`, iOS builder `m-medium`. |

`appVersionSource` is `remote`, so EAS owns the build number and version code. Do not bump
`buildNumber` or `versionCode` in `app.json` by hand, EAS will overwrite it and the two will drift.
The user facing `version` in `app.json` is still ours to set.

## Deploy the backend

The Supabase CLI is linked to the project already (`supabase/.temp/project-ref`).

```bash
supabase login
supabase link --project-ref nofawxywnhqrqnwokkge
supabase functions deploy settle-challenges
supabase functions deploy delete-account
```

**Do not use `supabase db push` here.** Apply a new migration by pasting the file into the Supabase
SQL editor. The CLI's migration history does not match the live database, see
[ARCHITECTURE.md](ARCHITECTURE.md#known-gaps-in-the-migrations).
